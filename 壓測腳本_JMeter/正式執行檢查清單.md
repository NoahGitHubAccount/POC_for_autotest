# 正式壓測執行檢查清單

> 執行前先確認 `shared\settings.bat` 已填妥（受測站 host、活動 pkid、JMeter 路徑），
> 且 `shared\sessions.csv` 的場次 pkid 為實際值。詳見本目錄 `README.md`。

---

## 一、正式執行前：先做 1 人演練

1. 瀏覽器登入受測站前台 → DevTools Console 執行：
   `JSON.parse(sessionStorage.getItem('logintoken')).access_token`
2. 輸出貼進 `shared\token.txt`（整行覆蓋，不含引號）
3. 雙擊 `rehearsal_1user\rehearsal_1user.bat`，等約 90 秒
4. 判讀（兩個地方）：
   - **黑視窗**：`summary = ... Err: 0 (0.00%)` ＝ 全部成功
   - **自動打開的 HTML 報告**：
     - 首頁 APDEX 表：`T1 取活動內容頁（含圖片）` / `T2 取報名頁動態表單` / `T3 送出報名` 三列都在
     - 左選單 **Statistics**：每段 Error % 應為 0.00%，並記下各段回應時間（正式跑要看的是同一張表）
     - 左選單 **Charts → Response Times Over Time**：正式跑時用來看「圖片會不會越跑越慢」

演練沒過就不要進正式——先照 `README.md` 的異常對照表排除。

---

## 二、正式執行（動作只有 3 步）

| 時點 | 動作 |
|---|---|
| T−10 分鐘 | 跟環境負責人確認伺服器就緒（若客戶承諾先擴充資源，此時確認已完成） |
| T−5 分鐘 | **重新取一次 token 貼進 `shared\token.txt`**（token 效期短，這步不能省）→ 可再跑一次演練當最後煙霧測試 |
| T | 雙擊 `prod_150users\run_150users.bat` → 輸入 `y` |

執行中（共 10 分鐘）黑視窗每 30 秒印一行 `summary +`，盯兩個數字：

- `Err: N`——一直是 0 就是順的；大量 401 ＝ token 過期（中斷、換 token 重跑）
- `Avg:`——平均回應時間，越跑越大代表伺服器開始吃力（這是正常的觀測目標，不用中斷）

跑完自動開 HTML 報告（`reports\run150_<時間>\report\index.html`），這份就是對外交付的依據。

---

## 三、事後驗證

1. 雙擊 `verify\check_registrations.bat` → 看同目錄產出的 `registrations.txt`，
   確認報名筆數與 `registrationSource=LoadTest` 的比數符合預期（**全 200 但沒進 DB ＝ 假成功**）。
2. 需要清理測試資料時，先用 `verify\list_events.bat` 列出活動並人工審查標記，再決定刪除範圍。

---

## 四、異常處置

見 `README.md` §六「異常對照表」。原則：

- 演練結果不對 → 立即回報，離正式時點越早越好
- Connection refused / timeout 大量出現**本身就是壓測發現**，記下發生時間點，不要當成腳本錯誤直接中斷
