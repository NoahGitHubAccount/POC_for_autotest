> 目標：1 個使用者、1 次 Loop，用單一壓測 token 直接打 API（不透過畫面點選），跑完「查詢活動內容→查詢圖片→下載圖片→查詢報名表單→確認報名成功」全流程，含業主指定的**圖片載入**測試。
>
> 本目錄檔案：
> - `壓測腳本匯入指南.md`（本檔）
> - `task4_確認報名_body.json`（Task 4 的 POST body，直接複製貼上用）
> - `loadtest_token_parameter.csv`（Parameter 匯入用 CSV，供 Import from CSV File）
> - `task_list_reference.csv`（全部 Task 規格一覽表，可用 Excel 開啟對照）
> - `script_editor_全部Task.js`（**Script Editor 用**：GUI 手動建 Task 卡住時的替代做法，見下方「Q：有沒有匯入功能？」）

## Q：我只能手動建立 Task 嗎？有沒有匯入功能？

**專案層級沒有「匯入任意 Task 清單」這種功能。** 查證過官方文件（`ui_reference.html`），Import 選單唯一項目是「Import groups recorded」，那是用來匯入 AppPerfect 自家 **Functional Tester / Unit Tester** 錄好的專案，不是給 CSV/HAR/URL 清單用的。

**但有一條實質等效的路：Script Editor。** AppPerfect 底層把每個 Task 存成一段 JavaScript 函式（`executeTask_N`），UI 跟腳本是雙向同步的——改 UI 會反映到腳本，改腳本也會反映到 UI。也就是說你可以**不點 GUI，直接貼程式碼**，一次貼完全部 7 個 Task：

1. `Project → Script Editor...`（或工具列的 Script Editor 按鈕、或右鍵 Editor Tree 選 Script Editor...）
2. 把本目錄 `script_editor_全部Task.js` 的內容整段貼進去（貼在最前面即可，裡面已經包含 `executeTask_1` ~ `executeTask_5` 共 7 個函式，對應 Task1/Task2/Task2b/Task2c/Task3/Task4/Task5）
3. 存檔並按 **Compile**（工具列/選單都有）
4. 關閉編輯器，UI 樹狀圖應該會自動長出 Task1~Task5 節點
5. 用 `Project → Verify Test Using Browser...` 驗證（同 Step 4）

這個檔案已經用查證過的 API 簽章寫好（`engine.createGetRequest/createPostRequest`、`request.addHeader`、`request.addRequestEntity`、`request.setExpectedResponseCode`、`engine.execute/release`），Task 4 的 body 跟 `task4_確認報名_body.json` 內容一致，Task 5 會自動從 Task 4 回應解析 `registrationId`。

**關於你遇到的「Invalid host information provided: Empty host information」**：這個錯誤在點擊**空的** ActionGroup 節點時就跳出，代表問題不在你要新建的 Task 本身（你還沒機會輸入 Host），比較可能是專案裡**其他**節點（例如 Starting Task Group 或 Ending Task Group）殘留了一個沒填 Host 的空 Task，UI 在畫樹狀圖/做整專案驗證時連帶掃到而報錯。建議：
- 檢查 Starting Group / Ending Group 底下是否也有殘留的空節點，刪掉試試
- 如果都排除了問題還在，直接跳過 GUI，改用上面的 Script Editor 貼入法——這樣完全繞開「Add Task Manually」精靈的驗證邏輯，能不能點開 ActionGroup 都不影響

## ⚠️ 重要更正（相較先前口頭給的版本）

先前口頭給的方案誤判「Host 只有一個」，實測後發現**圖片下載走不同網域**：

| 用途 | Host |
|---|---|
| 一般 API（活動資訊/表單/報名/憑證） | `qa-khcg-ai.foxconn.com` |
| **圖片下載**（FileResource） | `qa-citygpt.foxconn.com` |

兩者都需要帶 `Authorization: Bearer <token>`，同一個 token 兩邊都能用（實測確認 200，圖片端點不需要 Cookie）。

**已用官方 API 文件交叉驗證**（`https://qa-khcg-ai.foxconn.com/reventmodule/maas/index.html#/` 背後的 swagger.json，405 支端點）：`reventmodule` 只有 `POST /reventmodule/File/EVEventMedia/{id}/Image`（**上傳**圖片用），完全沒有下載端點——證實圖片下載本來就是設計成走獨立的檔案儲存服務（`qa-citygpt.foxconn.com/rstorage/...`），不是 reventmodule 自己提供，我們抓到的下載網址是唯一路徑，不是繞過官方 API 的偏門做法。

## 目前已知限制

- 壓測用活動複製品（pkid `34185325523320832`）**沒有圖片**（Clone API 不會複製媒體資料）。因此 Task 2（查詢媒體清單）改指向**來源活動** `34123425668794368`（同名「2026大港閱冰冰品嘉年華：最佳人氣由你來決定」，有真實封面圖）取得圖片清單；Task 1/3/4/5 仍然打你的壓測活動 `34185325523320832`。這不影響「圖片下載會不會卡」的測試目的——圖片本身存在同一個儲存服務，跟掛在哪個活動名下無關。
- 目前只測**封面圖**（PC + 行動版各一張），活動簡介等富文字內容裡若有額外嵌入圖片不在本次範圍內。

## Step 0：Project Properties（1 使用者、1 次 Loop）

1. 開啟/新建 AppPerfect LoadTest 專案
2. `Project → Properties Editor...` → **Run Settings** tab
3. 設定：
   - Load Strategy：`Loop`
   - Loop Count：`1`
   - Virtual Users：`1`

## Step 1：取得壓測 token（你自己操作，不透過 AI）

1. 用公民帳號登入 QA 前台（手機認證那個流程）
2. 開瀏覽器 DevTools → Console，貼上執行：
   ```js
   JSON.parse(sessionStorage.getItem('logintoken')).access_token
   ```
3. 複製輸出的字串（不含引號）
4. **建議在按下 AppPerfect 的 Run 之前 5 分鐘內才做這步**，避免設定期間 token 過期

## Step 2：把 token 填進腳本（⚠️ 2026-07-13 定案做法，不再使用 Parameter）

> **先前「建立 Parameter（LOADTEST_TOKEN）」的做法已废弃**。實戰踩坑：`addHeader` 第三參數指到的 Parameter 若不存在，AppPerfect 會**靜默丟棄整個 Authorization Header**（不報錯），而 Parameter 建立精靈的 Association 頁按 Cancel 會整個放棄建立、按 Finish 又可能誤關聯到 URL Path 等不相干欄位，極易鬼打牆。定案：**token 直接寫在腳本第一個變數**，完全不碰 Parameters 機制。

1. 開啟 `Project → Script Editor...`，全選刪除，貼上 `script_editor_全部替換版.js` 完整內容
2. **只改第 6 行**：把 `REPLACE_ME` 換成 Step 1 複製的 access_token（保留 `Bearer ` 前綴與空格）：
   ```js
   var LOADTEST_TOKEN = 'Bearer eyJhbGci...你的token...';
   ```
3. Save + Compile → 關閉編輯器
4. token 過期時：回 Script Editor 改第 6 行 → Compile → Run，其他都不用動

（`loadtest_token_parameter.csv` 保留供未來多帳號壓測時改回 CSV Parameter 方案參考，目前用不到）

## Step 3：用「Add Task Manually」依序建立 7 個 Task

每個 Group（建議都放同一個 Action Group）右鍵 → **Add Task Manually**，對照 `task_list_reference.csv` 或下表逐一填入。**所有 Task 的 Request Header tab 都要 Add 一筆**：
```
Authorization: Bearer @LOADTEST_TOKEN@
```
（值輸入 `@LOADTEST_TOKEN@` 這個語法，或用 Parameterize 按鈕關聯到剛建立的 Parameter）

### Task 1 — 查詢活動內容
- Task Details：Method=`GET`，Host=`qa-khcg-ai.foxconn.com`，Path=
  ```
  /reventmodule/Entity/EVEvent?ids=34185325523320832&bindUserData=true
  ```
- Response Code：`200`

### Task 2 — 查詢活動媒體清單（圖片測試第一步）
- Task Details：Method=`GET`，Host=`qa-khcg-ai.foxconn.com`，Path=
  ```
  /reventmodule/Basic/EVEventMedia?eVEventIds=34123425668794368
  ```
- Response Code：`200`

### Task 2b — 下載封面圖（PC版，213KB）★業主指定的圖片載入測試
- Task Details：Method=`GET`，**Host=`qa-citygpt.foxconn.com`**（注意換網域），Path=
  ```
  /rstorage/Extended/FileResource/34184848690100224
  ```
  ⚠️ 這裡要用 Task2 回應裡的 **`fileResourceId`欄位**，不是那筆媒體記錄自己的 `id`（兩者是不同值，之前記錯過）
- Request Header：除了 Authorization，**這支還需要額外 2 個 Header**（實測攔截真實瀏覽器流量才發現，這個端點走 Azure API Management 閘道）：
  ```
  ocp-apim-subscription-key: REPLACE_ME
  x-api-version: 1
  ```
- Response Code：`200`

### Task 2c — 下載封面圖（行動版，82KB）★業主指定的圖片載入測試
- Task Details：Method=`GET`，**Host=`qa-citygpt.foxconn.com`**，Path=
  ```
  /rstorage/Extended/FileResource/34184848895096832
  ```
- Request Header：跟 Task 2b 一樣，除了 Authorization 還要加:
  ```
  ocp-apim-subscription-key: REPLACE_ME
  x-api-version: 1
  ```
- Response Code：`200`

> Task 2b/2c 刻意拆成**兩個獨立 Task**（不是塞進 Task 2 的 Sub Tasks），這樣 AppPerfect 執行報告（Run Report）會分別列出每張圖片各自的回應時間，之後擴大壓測人數時就能直接看出「哪一張圖、多少併發時開始變慢」，符合業主要看「load 圖片會不會卡」的需求。

### Task 3 — 查詢報名表單欄位
- Task Details：Method=`GET`，Host=`qa-khcg-ai.foxconn.com`，Path=
  ```
  /reventmodule/Basic/EVFormField?eVEventIds=34185325523320832&category=Registration&pageRows=999
  ```
- Response Code：`200`

### Task 4 — 確認報名（送出，最關鍵的一支）
- Task Details：Method=`POST`，Host=`qa-khcg-ai.foxconn.com`，Path=
  ```
  /reventmodule/Entity/EVRegistration
  ```
- Request Header：除了 Authorization，**再加一筆**：
  ```
  Content-Type: application/json
  ```
- Request Entity tab：打開本目錄的 `task4_確認報名_body.json`，把裡面內容整段複製貼上（已經是真實的 eventId/formFieldId/sessionId，不用再改）：
  ```json
  {
    "evEventEntity": {"key": "34185325523320832"},
    "evRegistrationDatas": [
      {"evFormFieldEntity": {"key": "34185325526138880"}, "value": "1"}
    ],
    "evEventSessions": [{"key": "34185325525680128"}],
    "registrationSource": "LoadTest"
  }
  ```
  （這個 body 只填了必填欄位「參與人數」=1；「姓名」欄位非必填故省略）
- Response Code：`200`或`201`（實際以 Verify 結果為準）

### Task 5（可選）— 憑證 QR
- Task Details：Method=`GET`，Host=`qa-khcg-ai.foxconn.com`，Path=
  ```
  /reventmodule/Fetch/EVTicket/Qrcode/{registrationId}
  ```
  `{registrationId}` 要從 Task 4 執行後的回應 body 裡的 `id` 欄位人工抄過來替換
- Response Code：`200`

## Step 4：驗證（Verify Test Using Browser）

`Project → Verify Test Using Browser...`，逐一檢查：
1. 每個 Task 的 Request Header 是否真的帶了 `Authorization: Bearer <token>`（不是還顯示 `@LOADTEST_TOKEN@` 字面值）
2. Task 2b/2c 的回應是否真的是圖片（Content-Type: image/jpeg）
3. Task 4 送出的 body 是否跟上面 JSON 一致

## Step 5：執行與驗收

`Project → Run`，跑完後檢查 Run Report：

| 檢查項 | 通過標準 |
|---|---|
| Task 1/2/2b/2c/3 | 全部 200 |
| **Task 4** | 200/201，且回應 body 有新的 `id` 值（＝資料庫真的新增一筆報名記錄，這是「報名成功」鐵證） |
| Task 2b/2c 回應時間 | 記錄下來，作為之後擴大併發數的比較基準（這次 1VU 就是「不卡」的基準線） |
| 401 | 代表 token 過期，回 Step 1 重新取一次，只改 Parameter 的值即可，不用重建 Task |
| Task 4 若 400 | 看回應內容，常見原因：`同個場次不可重複報名`（同一個 token 對同一場次跑第二次會這樣，1VU/1Loop 階段不會遇到，多 Loop 時才要注意）|

## 之後擴大到多使用者前的已知限制（後端驗證規則挖出來的）

- **同一個 token 對同一場次不能報名第二次**——多 VU/多 Loop 時，每個虛擬使用者需要用不同 token（不同公民帳號），或者每輪切換不同場次
- 7 個場次各自有名額上限（測試活動預設較低，如需模擬 150 併發，記得先調整場次名額上限，避免還沒測到效能就先被業務邏輯擋下 400）
- Task 2b/2c 這兩張圖片檔案不大（213KB/82KB），如果業主想測「更大圖片、更多張圖片同時載入」的情境，需要另外找/上傳更大的測試圖片到壓測活動上
